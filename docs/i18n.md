# 国际化（i18n）接入指南

> 模板入口：`lib/i18n/` + `messages/`。新页面/新文案按本文件接入，保持全站一致。

## 架构

- **方案**：`next-intl`，**URL 不带语言前缀**（`localePrefix: "never"`）。
- **语言选择**：`NEXT_LOCALE` cookie（用户手动切换，有效期一年）> `Accept-Language`（首次访问，由 middleware 自动写入 cookie）。
- **默认语言**：`zh`。支持列表：`zh` / `en`（`lib/i18n/routing.ts`）。
- **切换器**：`components/i18n/LanguageSwitcher.tsx`（Header 右上角），调用 `/api/locale` 写 cookie 后 `router.refresh()`。

## 文件地图

| 文件 | 作用 |
|---|---|
| `lib/i18n/routing.ts` | 语言列表 / cookie / 路由策略 |
| `i18n/request.ts` | 服务端加载消息（next-intl 插件默认路径，自包含相对导入） |
| `lib/i18n/navigation.ts` | `Link`/`useRouter`/`usePathname` 本地化封装 |
| `messages/*.json` | 18 语言消息字典（命名空间分块，3258 键） |
| `middleware.ts` | i18n cookie + Supabase 会话检查组合 |
| `app/api/locale/route.ts` | 语言切换 cookie 写入 |
| `next.config.ts` | `createNextIntlPlugin` 已注册（构建期静态页面可正常取词） |

## 新文案接入模板

1. 在 `messages/zh.json` 与 `messages/en.json` **同一路径**各加一条（两个文件结构必须一致）。
2. 命名空间按界面分块：`Header` / `Login` / `Account` / `Invite` / `Metadata`。新模块页新增自己的命名空间（如 `Pose`、`Pricing`）。
3. 服务端组件：
   ```tsx
   import { getTranslations } from "next-intl/server";
   const t = await getTranslations("Pose");
   <h1>{t("title")}</h1>
   ```
4. 客户端组件：
   ```tsx
   import { useTranslations } from "next-intl";
   const t = useTranslations("Pose");
   <h1>{t("title")}</h1>
   ```
5. 带变量文案用 ICU 语法：`"heroDesc": "你获得 {inviter} 灵点"` → `t("heroDesc", { inviter: 100 })`。

## 数据驱动文案模板（导航类）

`lib/navigation.ts` 中的条目带 `label: 中文兜底` + `labelKey: "Header.modules.xxx"`，
消费方渲染时优先取翻译：`{item.labelKey ? t(item.labelKey) : item.label}`。
新增模块导航项时同时补 `messages` 里的 `Header.modules.*`。

## 注意事项

- 客户端组件里**不要**从 `next/navigation` 导入 Link/useRouter，用 `lib/i18n/navigation` 的封装。
- 两个语言文件键结构必须完全一致，否则英文环境会回退显示键名。
- 中文是默认语言：`zh.json` 是权威来源，新增文案先写中文再翻译英文。

## 键约定（必须遵守，2026-08 审查后统一）

next-intl 的命名空间 t 会自动加前缀，键必须与消费方的 t 匹配：

1. **页面本地数据数组**：相对键（`"models.desc"`）+ 本页命名空间 t 渲染。
2. **数据要传入共享组件**（共享组件用全局 t）：先用 `qualifyOptionKeys(items, "Pose")`（lib/i18n/options.ts）把键转成全路径。
3. **lib 数据**（navigation.ts 等）：直接存全路径键（`"Header.nav.products"`），渲染端用**全局 t**（`useTranslations()` 无参数）。
4. 判断错误会静默显示键名字符串（不报错），务必对照此表检查。

## 多语言排版最佳实践（已落地）

- **语言自动检测**：middleware 按 `NEXT_LOCALE` cookie > 浏览器 `Accept-Language` 协商（行业标准）。
  用户手动选择后 cookie 生效一年，**绝不再次自动切换**。不用 IP 定位判语言（行业共识：语言 ≠ 位置）。
- **RTL（阿拉伯语）**：根布局按 locale 输出 `dir="rtl"`；`app/styles/i18n.css` 统一处理方向性图标翻转、
  连写文字禁字距、`code` 保持 LTR 嵌入；输入框图标用 Tailwind `rtl:` 变体翻转（参考登录页写法）。
- **字体**：Geist 只覆盖拉丁；CJK/阿拉伯/西里尔/泰/天城文走系统字体回退链（见根布局 fallback）。
- **数字与日期**：客户端用 `Intl.NumberFormat(document.documentElement.lang)` 本地化（参考 InvitePanel）。
- **切换器排版**：原生语言名展示（对本族人显示本族文字），当前语言高亮 + 勾选，移动端平铺网格。
