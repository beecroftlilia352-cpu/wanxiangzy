# AI 模型控制面与智能路由

## 目标

统一管理图片、文本、视觉、视频、音频与向量模型。业务页面只提交“逻辑模型 ID”，不接触供应商地址、密钥或精确上游模型名称。管理员在 `/admin/providers` 维护逻辑模型、供应商端点、部署映射、容量和路由策略。

## 核心分层

1. **逻辑模型**：用户看到的产品，例如 `nano-banana-2`、`qwen-image-3`。除能力和价格外，可配置标题、短标题、描述、徽标、图标、封面、分组、标签、排序、推荐状态及多语言覆盖。图片模型必须配置至少一个正数积分价格后才能设为用户可见。
2. **供应商端点**：一个可认证的 API Base URL。API Key 使用 AES-256-GCM 加密，或保存成 `env:VARIABLE_NAME` 引用；客户端永远只看到脱敏状态。
3. **模型部署**：逻辑模型到供应商及精确上游模型名的映射，同时配置协议适配器、优先级、权重、并发、RPM、burst、成本和质量分。
4. **全局策略**：最大尝试次数、退避、熔断和智能评分权重。

同一逻辑模型、相同优先级的部署构成一个“供应商池”。系统先在该池内按容量与权重分流；只有池内全部满载、限流、熔断或调用失败时，才进入下一优先级。因此“负载均衡”和“故障兜底”是串联的两个阶段，不会互相冲突。

## 路由行为

### 协议适配与供应商差异

路由器只接收内部标准任务，不直接拼供应商请求。每个部署绑定一个受测试的协议适配器：适配器负责请求体、鉴权、同步/异步提交、轮询和响应归一化。相同逻辑模型因此可以把 OpenAI Images 兼容供应商与 Gemini Native 供应商放进同一优先级池，路由算法无需理解二者格式差异。

控制台允许部署级选择受限鉴权方式（Bearer、`x-api-key`、`x-goog-api-key`），覆盖安全的相对生成/编辑/状态路径，以及少量 primitive 静态参数。标准的模型、提示词、图片和任务字段最后写入并保持最高优先级，静态参数无法覆盖它们；路径禁止绝对 URL、`..`、query/hash 以及未知占位符。API Key 值仍由服务端适配器注入。若上游拥有全新的请求或响应结构，应在 `lib/ai-control-plane/adapters.ts` 注册并实现代码适配器及契约测试，而不是开放任意脚本或任意 JSONPath。

当前可执行适配器：`openai-image`、`gemini-native`、`openai-chat`、`newapi-video`。模型目录可以登记音频和向量模态，但只有绑定了对应且已实现的协议适配器后才能发布为可执行部署。

### 稳定路由

同优先级池使用基于请求 ID 的加权 rendezvous 排序。相同请求决策稳定，不依赖共享轮询计数；权重决定长期流量份额。排序后仍需取得原子容量租约，失败会尝试池内下一部署。

### 智能路由

同优先级池先按下列归一化指标得到动态健康分：

- EWMA 成功率
- EWMA 延迟
- 配置成本
- 实时剩余容量
- 人工质量分

动态健康分会转换成“有效权重”，再与管理员配置的池内权重一起进入加权 rendezvous。这样健康供应商会获得更多流量，但不会出现所有串行请求都打到同一个最高分节点的热点；并发租约和滚动 RPM 仍是最终硬门槛。

用户可在账户设置选择“稳定优先”或“智能路由”。智能路由只在同一逻辑模型的供应商之间选择，不会偷偷换成价格或能力不同的模型。配置结构预留了 `compatibleFallbackModelIds`，但当前用户 API 和任务执行器均强制关闭跨模型替代；只有未来具备显式能力校验、价格确认和用户同意后才可开放。

### 容量、限流与熔断

- `maxConcurrency`：供应商部署的同时运行上限。
- `requestsPerMinute + burst`：60 秒滚动窗口准入上限。
- Redis 有序集合原子完成租约、过期清理和 RPM 记账；进程崩溃后租约会按 TTL 自动释放。
- 所有候选部署暂时满载或处于冷却时，路由器抛出专用容量背压信号；生成任务通过 `defer_generation_for_ai_capacity()` 原子回到队列并设置 `next_attempt_at`，不会退款、不会消耗三次业务失败额度，也不会让 Worker 忙等。到期后由 `FOR UPDATE SKIP LOCKED` 重新认领。
- 429 会进入限流冷却；连续失败达到阈值后打开熔断器；冷却结束仅允许 `halfOpenMaxRequests` 个探测请求。
- 多实例生产环境必须配置标准 Redis 的 `REDIS_URL`（支持 `redis://` 或 `rediss://`），并使用 `AI_ROUTER_CAPACITY_MODE=redis`。该 Redis 与 BullMQ 共用连接端点但使用独立 key 命名空间；`local` 仅用于开发或单进程故障演练。

## 数据与隐私

迁移文件：`supabase/ai-control-plane.sql`。

- `ai_provider_health`：部署级 EWMA、熔断与限流冷却状态，仅 service role 可读写。
- `ai_route_attempts`：每次上游尝试的路由原因、耗时、状态、用量、成本和输出尺寸。禁止保存提示词、图片内容、API Key、Authorization 或完整上游响应。
- `ai_user_routing_preferences`：用户自己的路由偏好，通过 RLS 仅本人可读写。
- 配置快照继续使用 `admin_config_versions` 的 `ai.control-plane.v1`，发布与回滚均为追加式版本，便于审计。
- `maintain_ai_route_attempts()`：每小时由 Supabase Cron 分批运行；把超过 90 分钟仍为 `running` 的孤儿尝试标为 `cancelled`，并按 90 天保留期分批删除明细。`created_at` 使用 BRIN 索引控制时序数据维护成本。

原始上游错误消息可能回显提示词或凭据，因此数据库只保存标准错误分类、HTTP 状态与错误码。

## 新增模型操作手册

1. 在“模型目录”新建逻辑模型，填写稳定 ID、模态、能力，以及前端标题、描述、图片、徽标、排序和多语言展示信息。
2. 图片模型填写受支持规格的积分价格；留空代表不支持该规格。
3. 新建或复用供应商端点，配置 HTTPS Base URL 和密钥，先执行连接测试。
4. 新建部署，选择协议并填写精确上游模型名称。
5. 同级池使用相同优先级；用权重表达流量份额。备用供应商使用更大的优先级数值。
6. 配置并发、RPM、成本和质量分，先保存草稿并校验。
7. 小流量发布，观察 24 小时成功率、P95、429 和熔断状态，再逐步调整权重。

OpenAI Images 兼容模型使用 `openai-image`；Gemini 原生 `generateContent` 使用 `gemini-native`；OpenAI 兼容文本/视觉使用 `openai-chat`；现有 NewAPI 视频网关使用 `newapi-video`。控制台只允许选择已经具备完整请求转换、响应归一化和运行时测试的协议；`OpenAI Responses` 或自定义 HTTP 必须先新增代码适配器和契约测试，不能仅靠配置冒充支持。

默认草稿还为三个内置图片模型提供 `api.new.bi` 的 `openai-image` 低优先级备用部署（`newapi-image`）。它只在同一逻辑模型的主部署失败或不可用时接管，不进行跨模型替换；图片编辑请求的原图与 mask 会继续由协议适配器透传。未配置 `VIDEO_API_KEY` 时该供应商会自动退出候选池。发布前仍需在后台连接测试确认账户实际开放对应上游模型与 `/images/edits`，未通过时应禁用对应部署。

## 发布、回滚与故障演练

- 发布前：连接测试、配置校验、Redis 连通、至少两个供应商的低成本探测。
- 发布：后台“发布”会原子归档旧版本并写入新版本；应用侧配置缓存最多 5 秒。
- 回滚：在“版本与回滚”选择历史版本，系统会把其内容作为新版本发布，不修改审计历史。
- 演练：对主供应商设置极低 RPM 或临时禁用，确认同级池/下一优先级接管；恢复后观察半开探测再闭合。
- 告警建议：5 分钟成功率低于 95%、P95 超过业务 SLO、429 超过 3%、全部部署不可用、Redis 容量服务不可用。

## 降级原则

旧版 `model.providers`、`llm.providers`、`video.providers` 在首次发布统一配置前会被只读适配，避免上线瞬间中断。统一配置一经发布，即以 `ai.control-plane.v1` 为唯一运行时事实来源。不要同时修改旧配置期待覆盖新控制面。
